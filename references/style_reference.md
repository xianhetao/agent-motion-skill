# 口播包装 · 风格参考与样张方法论

> **来源**：huashu-design 3.0（花叔，2026-10-23 发布）—— 它是本技能「路线 C」引擎 `huashu-motion` 背后的设计方法论。
> 这篇文章把「怎么选风格、怎么给 agent 看得见的参考、怎么避免每支片长得一样」讲透了，
> 本文件把它提炼成口播包装可直接套用的版本。
> **背景**：huashu-design 2.0 治的是「无聊」，但用了四个月发现新问题——**单个项目看都不错，放一起却长得像**
> （暖纸底+衬线+陶土色反复出现）。3.0 的解法不是加禁令，而是「加选项、给样张、做账本」。

---

## 0. 为什么单独写这一份

本技能已有 `design_principles.md`（用户反复验收拍板的**硬规则**）和各路线工作流，但
**「风格怎么选、参照物怎么给、怎么避免千篇一律」**一直缺方法论。这正是 huashu-design 3.0 的核心，
把它沉淀成口播版，让每次包装都「敢做、不撞、看得见」。

---

## 1. 第一性原则：加选项，不加禁令

3.0 最反直觉的教训（花叔盲测三轮验证）：

> 你告诉 agent「不许用什么配色/字体/版式」，它会躲到**最安全、最整齐、最无聊**的地方去；
> 你给它**更多看得见的东西**（样张、参考板、候选方向），它反而敢做、做得出彩。

**落地到本技能**：

- `design_principles.md` 的硬规则是用户**反复验收拍板**的审美底线，**必须守**——它不是「禁令式约束」，
  而是已验证的对错线（如「横画发虚的字体不能用」「组间距不能大于内容区」）。
- 但**风格多样性**不要用禁令表达（「别用暖纸」「别用衬线」是**错误写法**）；
  改成**给候选**：「可走 暖纸 / 暗场 / 杂志 / 科技 四选一，各出样张再定」。
- 给指令 / 写 config 时，列「可选方向 + 样张」，而不是列「不要做 X」。

---

## 2. 先出候选方向，再定稿

3.0 做法：**三套逻辑各出两个候选 → 画缩略图 → 挑「够好、彼此不一样、不撞近期项目」的三版做完整设计。**

**口播落法**：

- 开工前先给 **2–3 个视觉方向**（配色 + 版式 + 参考片），用样张/缩略图摆出来让用户选，
  **不要一头扎进渲染**。
- 三选判断标准：
  1. **够好**：满足 `design_principles.md` 硬规则；
  2. **彼此差异明显**（不是只换色）；
  3. **不撞用户最近几支片的外观**（见 §5 外观账本）。
- 工具：`scripts/font_compare.py`（字体样张）、`scripts/ref_board.py`（参考片关键帧板）、HTML 缩略图。

---

## 3. 参考板（ref_board）：同媒介、先截图

3.0 做法：做 App 找**获奖 App**、做网页找获奖网页，新加 `ref_board.py` 把参考作品截成参考板，
**agent 亲眼看过再动手**。核心铁律：**参照物必须是同媒介的**（别拿平面海报去参考视频）。

**口播落法**：参考片必须是**同形态口播/短视频**（竖屏 talking-head、知识解说、品牌口播），
不是宣传长片或平面物料。

```bash
# 给定若干参考短视频，用 ffmpeg 抽关键帧拼成带时间戳的参考板 HTML
python3 scripts/ref_board.py ref1.mp4 ref2.mp4 --out board.html --frames 6
python3 scripts/ref_board.py ref1.mp4 --at 3,12,40 --out board.html        # 指定时刻抽帧
python3 scripts/ref_board.py ref1.mp4 ref2.mp4 --label "竖屏知识解说:品牌口播" --out board.html
```

- 抽帧完先让用户/agent **看板**再定视觉方向，不要凭空想象。
- 看板走本地 server 截图（`file://` 对图片没问题，但字体/样张若有 webfont 需注意 CORS；
  稳妥做法：`python3 -m http.server` 起本地服务 + Chromium fullPage 截）。

## 4. 风格库：给样张，不给禁令

口播常用视觉方向（都在 `design_principles.md` 硬规则内可实现，差异在**配色气质 + 版式**）：

| 方向 | 配色气质 | 适用题材 | 样张思路 |
|---|---|---|---|
| **暖纸 editorial** | 纸面 `#f2f1ec` / 墨 `#26282e` / 朱红 `#b8433f` | 知识讲解、观点输出 | 杂志书页感；大标题 + 朱红 rule；衬线/无衬线可选 |
| **暗场展柜** | 近黑底 + 单一点缀色 | 科技、产品、高端 | 暗底巨字、细位置条、高对比、绢地取色 |
| **杂志 grid** | 白底 + 强网格 + 一种强调色 | 企业宣传 | 多栏网格、数字卡醒目、栏目化 |
| **科技冷感** | 冷灰蓝 + 青色高亮 | 数据汇报 | 等宽数字、线框、冷调、信息密度高 |

- 每个方向先出**样张**（`font_compare.py` + 一张排版示意），确认再渲。
- 风格库随项目扩充（3.0 从 60→84 种，每种一张样张）；口播不必那么多，但**新增方向要配样张**。

## 5. 外观账本 + 成片体检（design_lint）

3.0 的「越用越懂你」三件套（本机记录，不上传）：

- **经验**：开工前带出用户说过的品味原话；收工时记值得记的。
- **外观账本**：每次交付记一笔「长什么样」，下个项目**主动避开**近期外观 —— 直接治「放一起像」。
- **设计体检**（`design_lint.py`）：**只量能核对的事实**，不打分：裂图、字太小、对比度不够、
  三版是不是换皮、和最近项目撞没撞。

**口播落法**（成片体检清单见 `review_loop.md`）：

- 外观账本：交付时记一笔「这支片用了什么配色/版式/方向」，下次主动错开。
- 成片体检（只查事实）：① 裂帧/黑帧 ② 字太小（屏摄后看不清）③ 对比度（浅字浅底）
  ④ 是否与近期项目撞外观 ⑤ 是否某段「换皮」（只改色不改结构）。
- 事实核实：数据/出处——初稿后开核查环节对着源数据核对（见 §6）。

---

## 6. 事实先核实

2.0 就定下的规矩：**任何数据/出处，初稿后开一个核查环节对着原文/源数据核对。**
口播的数据卡（count-up）尤其要核「说的是数量、倍数还是百分比」——花叔案例里韦伯望远镜初稿
把「数量多约 100 倍」读成「亮 100 倍」，被独立核查 agent 抓出。我们对数据块已做点核对，
可进一步：每页右下角标出处（可行时），复杂数据交给独立核查。

## 7. 与本技能其它文件的分工

| 文件 | 职责 |
|---|---|
| `design_principles.md` | 用户拍板的**硬规则**（对错线，必须守） |

| `planning_guide.md` | 先出候选方向 → 读片 → 标锚点 → 落 config |
| `review_loop.md` | 验收迭代 + 成片体检清单 |
| `scripts/font_compare.py` / `scripts/ref_board.py` | 样张 / 参考板工具 |
