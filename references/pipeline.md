# agent-motion · 全流程方案（Pipeline）

> **本文件定位**：把"给一段口播 → 成片"的**完整决策流**讲清楚：先设计关键帧、再定段落（抽象就让人讲）、再按片长定节奏、再定技术（画中画/抠像）、渲染前与用户对齐、最后才渲染。
> 它管"**什么时候做什么决策、按什么规则决策**"；具体的视觉/动效对错线在 `design_principles.md`，风格怎么选在 `style_reference.md`。
> **一句话**：本文件是"流程与决策"，那两份是"规范与样张"。

---

## 0. 复盘：三套来源与来龙去脉

### 0.1 花叔 huashu 体系（路线 C 引擎 + 方法论）
- **huashu-motion**：talking-head 模板 + `om` CLI，导演式合成（数据卡 / 花字 / 章节 / 名牌按口播 cue 卡点）。
- **huashu-design 3.0（2026-10-23）**：风格选择方法论——**加选项不加禁令**、先出候选方向再定稿、参考板同媒介先截图、外观账本 + 成片体检、事实先核实。
- **huashu 动效系统**：Easing 库 4 条（expoOut / overshoot / expoIn / linear，禁用其它）+ Duration 字典（小 300 / 中 500 / hero 700–900ms，退场永远快于入场）+ Stagger（相邻 30–80ms）+ Human-Centric Pausing（关键结果前强制停 ≥300ms）。
  → 已沉淀进 `design_principles.md` §3，渲染时必须逐条遵守。

### 0.2 agent-motion 既有沉淀（鹅总早期构想 + test-01 多轮迭代）
- 早期：talking-head 引擎、关键帧系统、画中画小窗、混剪思路。
- test-01 v1→v18（14 轮验收）：沉淀动效/排版硬规则（即今天的 `design_principles.md`）。
- 痛点：模板不够时要逐元素控制只能走路线 D（原生 Three.js 工程），开发量大、每次改动重渲。

### 0.3 本次协作新增（2026-10-24，已验证）
- **去人物、满屏演绎**：段落核心句出大标题占满、论证里抓关键词做动画、满屏内容演绎、格式塔分组无大空白。
- **4 章风格映射**：门槛=民国报刊题签框 / 公信力=暗场展柜 / 洁丽雅=杂志 grid / 原则=书籍朱砂印。
- **WCAG 对比度固化**：`scripts/wcag_check.py` + 已验证调色板（深琥珀 `#8f5f12`、深红 `#9e2b25` 替代亮橙）。
- **动画基本规则规范**：`design_principles.md` §3 重写为可执行参数（曲线库 / 时长分级 / 硬间隙 / Human-Centric Pausing）。
- **混排决策 + 节奏规划**：人在讲（原片全屏 + 关键字）/ 纯动效（满屏关键帧）/ 混合；以及"按片长定呼吸节奏"的雏形。

> 本文件把 0.3 的"节奏 + 混排 + 决策流"正式立为流程，串起 0.1 / 0.2 的既有能力。

## 1. 总体流水线（7 个阶段）

```
P0 输入与理解 → P1 关键帧设计 → P2 段落决策 → P3 节奏规划
             → P4 技术决策 → P5 渲染前对齐 → P6 渲染执行 + QC
```

| 阶段 | 输入 | 产出 | 关键动作 |
|---|---|---|---|
| **P0 输入与理解** | 口播视频 + 文字稿（或 ASR） | 语义单元切分、口播词时间轴 | 看片 + 读字幕；拆 U01..Un；标每段口播起止与核心论点 |
| **P1 关键帧设计** | 文字稿 + 语义单元 | 静态关键帧图 + 风格标注 | 每个关键论点/数据/对比 → 1 张关键帧；从风格库选配色版式；画"大标题/关键词/数据卡"草图 |
| **P2 段落决策** | 语义单元 + 关键帧 | 每段的「模式」标签（人讲 / 动效 / 混合） | 抽象→人讲；具象/数据/对比→动效；引入过渡→混合 |
| **P3 节奏规划** | 片长 + 各段模式 | 整片节奏表（何时人/动/混合、各自时长） | 按疲劳阈值排呼吸节奏，避免长段纯口播或纯动效 |
| **P4 技术决策** | 原片素材 + 混合段 | 画中画/抠像决定 + 混排布局定稿 | 原片能否抠像？混合段人位/动效位定下来 |
| **P5 渲染前对齐** | 节奏表 + 关键帧 + 布局 | 用户拍板的方案（含 2 个样本段预演） | 用户与 agent 锁定：节奏、动画样式、人位/动效位、全局规范 |
| **P6 渲染执行 + QC** | 锁定方案 | 成片 | 逐段渲（全局规范）+ 拼接 + 成片体检 |

**铁律**：P0–P5 不写渲染代码，只在 P5 用户拍板后才进 P6。任何"先渲出来看看"都是错的——先对齐再渲染。

## 2. P1 关键帧设计（文字稿 → 画面方案）

**目标**：在没渲染前，就把"这片子长什么样"用静态关键帧钉死。

1. **拆语义单元**：按口播自然停顿切 U01..Un（参考 `planning_guide.md` 的分镜方法）。
2. **每单元 → 1（或几）张关键帧**：
   - 关键论点 → 大标题占满帧
   - 数据/对比 → 数据三联 / 两卡对比帧
   - 层级关系 → 树状 / 结构图帧
3. **风格匹配**（从 `style_reference.md` §4 风格库选，按段落气质）：
   - 观点/批判 → 暖纸 editorial（报刊框 + 朱红 rule）
   - 科技/高端 → 暗场展柜（近黑底 + 单点缀色）
   - 企业/数据 → 杂志 grid（白底强网格）
   - 严肃/结论 → 书籍朱砂印
4. **画草图**：用 PIL 直绘（`gen_keyframes.py` 思路）或 om 截图，输出 PNG + 索引页。
5. **设计硬规则**（必须守，来自 `design_principles.md`）：
   - 格式塔相近相邻、满屏无大空白、组间距 ≤ 组内行距
   - 大标题占满中上部、强冲击
   - 顶部章节小标签与标题重复 → 删小标签、标题上移补白
   - WCAG AA 对比度（`wcag_check.py` 核算每处文字-背景配对）

## 3. P2 段落决策（出不出画面演绎）

**核心原则（用户拍板）**：**特别抽象的段落，原则上就让人讲，不要出画面去演绎。** 画面演绎留给具象、可视觉化的内容。

| 段落性质 | 模式 | 画面 | 理由 |
|---|---|---|---|
| 抽象论述 / 复杂因果 / 建立信任 / 个人观点 | **人讲（A）** | 原片全屏 + 顶部提炼关键字 | 抽象内容强行可视化会变成空口号；人在讲建立可信度 |
| 具象数据 / 名词对比 / 案例爆发 / 结构关系 | **动效（B）** | 满屏关键帧动画 | 数据/对比天然适合视觉化，冲击强 |
| 引入 / 过渡 / 需辅助理解的论点 | **混合（C）** | 人 + 关键字 / 人 + 图文 | 人保持语境，动效辅助锚定关键词 |

**决策信号**：
- 一句话能用"数字/名词/对比"说清 → 动效（B）。
- 一句话是"因为…所以…但是…"的抽象推理、没有具体可画对象 → 人讲（A）。
- 段落既是论点引入、又带一两个可画关键词 → 混合（C）。

## 4. P3 节奏规划（基于片长的呼吸节奏）

**问题**：纯口播出镜太久观众会烦；纯动效太久会信息过载。要在两者之间排"呼吸"。

### 4.1 疲劳阈值（默认值，可调）
- **纯口播（A）连续上限 ≈ 30s**（竖屏短视频注意力下滑点；横屏/知识向可放宽到 45s）。
- **纯动效（B）连续上限 ≈ 20–25s**（信息密度高，久看累；climax 段可冲到 35s）。
- 任一模式逼近上限，下一次切换必须换形态（A↔B 或进 C）。

### 4.2 通用节奏模板（按片长缩放）
```
开场钩子(动 B) → 核心论点(人 A) → 数据/对比(动 B) → 案例(人+关键 C)
             → 高潮 climax(动 B) → 收尾结论(动 B 或 人 A)
```
- **短片（≤60s）**：1 次切换足够（开动 → 人讲到底，或开人 → 尾动）。
- **中片（60–180s，如本例 142s）**：2–3 次交替（人段 30–50s、动段 10–25s 穿插）。
- **长片（>180s）**：每 30–40s 必有一次形态切换，且动效段内部也按章节换风格（避免换皮）。

### 4.3 产出
- **整片节奏表**：每段的 `[起止时间, 模式 A/B/C, 时长, 风格]`。
- **切换点清单**：在哪些秒切换形态（硬切，背景同色直接硬切；见 `design_principles.md` §6）。

> 本例（洁丽雅口播 142s）节奏表见下方 §7 样例，可作模板复用。

## 5. P4 技术决策（画中画 vs 抠像 + 混排布局）

### 5.1 人 + 动效 怎么同框：先判背景，再定画中画 / 抠像

**决策第一问：原片背景是否适合抠像？**
- **背景干净、可抠** → 纯色 / 白 / 绿 / 蓝等干净背景，或素材自带 Alpha 通道。走**抠像**（绿幕色键 或 Alpha 通道；普通实景也可用 RVM 等 AI 抠像，但算力与边缘成本更高，仅在确需同台融合时上）。
- **背景复杂、抠不干净** → 绝大多数实景口播、环境杂乱。**直接走画中画，不做抠像**。

| 方案 | 适用 | 形状 | 优点 | 缺点 | 何时选 |
|---|---|---|---|---|---|
| **画中画 PiP** | 背景复杂、抠不干净 | **圆形或方形小窗**，置于输出画面某位置 | 零抠像成本、保留原片语境、稳 | 人是小窗，存在感弱 | **背景不可抠时的默认** |
| **抠像（绿幕 / Alpha）** | 背景干净纯色 / 自带 Alpha | 人真正融入场景 | 人 + 动效同台融合，沉浸 | 需干净背景或重拍 / AI 算力 | 仅当背景可抠 |
| **全屏人 + 动效嵌空白** | 关键帧未满屏、角落有空 | 全屏人 | 人仍是主体、不抢戏 | 仅限"中部满、角落空"的关键帧 | 混合段首选（如暗场两卡对比） |

### 5.2 混排布局库（定稿时选一种）
- **L1 全屏人 + 顶部关键字**：人在讲占满屏，头顶上方叠提炼关键字（不挡脸）。→ 本技能默认"人在讲"形态。
- **L2 画中画**：动效主体占大区，人缩角落**圆形或方形**小窗（边距 ≥44px，不挤其它元素）。背景不可抠时的默认混排。
- **L3 全屏人 + 动效嵌空白**：关键帧未满屏时，在空白处放人小窗（如 KF3 暗场两卡）。
- **L4 抠像同台**：背景干净（纯色 / 绿幕 / 自带 Alpha）才用；人 + 动效真正同帧合成（路线 D 原生工程能力；路线 H 待移植）。

### 5.3 边距与避让
- 小窗四周 ≥44px 边距（`design_principles.md` §7）。
- 关键字/动效不得压人脸主体（人在讲段：关键字放头顶上方；混合段：人窗放角落）。

## 6. P5 渲染前对齐（用户 + agent 必过清单）

**这是从"方案"到"渲染"的唯一闸门。** 渲染前必须和用户逐条对齐并拍板：

1. **整片节奏表**（§4.3）：何时人 / 何时动 / 何时混合，各自时长与切换点。
2. **每个动效段（B）的风格 + 关键帧样式**：配色版式（风格库）、大标题/数据卡/树图长什么样。
3. **每个混合段（C）的布局**：人位（角落/头顶）/ 动效位 / 选 L1–L4 哪一种。
4. **全局规范确认**：文字（`design_principles.md` §5）、图片（§4）、动效（§3）三份硬规则已读并采纳。
5. **样本段预演**：至少渲染 **1 段人讲 + 1 段动效** 小样给用户目测（验证技术方案 + 观感），确认后再全量。

> 对齐产出 = 一份"锁定方案"（节奏表 + 关键帧 + 布局 + 规范确认 + 样本目测 OK）。**没有这步不进 P6。**

## 7. P6 渲染执行 + 段落微调机制

### 7.1 渲染脚本（按模式选）
| 模式 | 脚本 | 说明 |
|---|---|---|
| 人在讲（A 模式）/ 混合 L1·L3 | `scripts/render_talk.py`（路线 H） | PIL 关键字层 + ffmpeg overlay 原片；20px expoOut 入场 + 硬间隙 |
| 纯动效（B 模式） | `scripts/render_anim.py`（路线 H） | PIL 逐帧 + ffmpeg 编码；tier 分级时长、段尾硬切 |
| 路线 C 导演式 | `huashu-motion` `om` | 标准化卡片/花字/章节模板（备选） |
| 路线 D 原生 | Three.js 工程 | 极致逐元素/3D 控制（重活，保留） |

> `render_talk.py` / `render_anim.py` / `gen_keyframes.py` 已提升为技能脚本（`scripts/`），可直接复用。

### 7.2 全局规范 vs 段落微调（用户要求）
- **全局规范**（文字/图片/动效）写在 `design_principles.md` + `style_reference.md` + `wcag_check.py`，**所有段默认遵守，不在渲染代码里另写一套**。
- **段落级细微调整**：若某段因内容特殊需偏离（如某大标题字号微调、某卡停留延长），**写在该段的独立 scene 文件 / 注释里**，不改全局；并在交付说明里点出"X 段因 Y 做了局部微调"。
- 原则：**全局定调、局部留痕、不污染通用规则。**

### 7.3 QC 与交付
- 逐段抽帧：对比度达标、人在讲段关键字不挡脸、纯动效段无裂帧/无大空白、拼接处音画对齐。
- 成片体检（只查事实）：裂帧 / 字太小 / 对比度 / 撞外观 / 换皮（`review_loop.md`）。
- 交付后清理中间产物（`delivery_cleanup.md`）。

## 9. 样例：洁丽雅口播（142s）节奏表（已验证，可作模板）

| 段 | 时间 | 内容 | 模式 | 画面 |
|---|---|---|---|---|
| U01 | 0:00–0:04 | 开场钩子·门槛没了 | B 动效 | KF1 大标题满屏 |
| U02 | 0:05–0:10 | 旧门槛三件套 | B 动效 | KF1 三证卡满屏 |
| U03 | 0:10–0:20 | 筛过一遍→稀缺→可信 | A 人讲 | 原片全屏 + 关键字 |
| U04 | 0:20–0:27 | 门槛归零→供给膨胀 | B 动效 | KF1 论证句满屏 |
| U05 | 0:27–0:38 | 选谁（问题聚焦） | A 人讲 | 原片全屏 + 关键字 |
| U06 | 0:39–0:57 | 筛选和把关（核心） | A 人讲 | 原片全屏 + 关键字 |
| U07 | 0:57–1:07 | 公信力不稳 | B 动效 | KF3 大标题满屏 |
| U08 | 1:07–1:18 | 机构给的 vs 算法给的 | B 动效 | KF3 两卡（满屏，不放人） |
| U09 | 1:19–1:23 | 洁丽雅引入 | A 人讲 | 原片全屏 + 关键字 |
| U10 | 1:23–1:40 | 数据爆发 1.2亿/22.8万/500万 | B 动效 | KF4 数据三联满屏 |
| U11 | 1:40–1:56 | 报案三连（climax） | B 动效 | KF5 三卡满屏 |
| U12 | 1:58–2:06 | 压进去的是品牌资产 | A 人讲 | 原片全屏 + 关键字 |
| U13 | 2:06–2:22 | 主号保调性（树图） | B 动效 | KF6 树状图满屏 |

**时长汇总**：人讲(A) ≈ 53s ｜ 纯动效(B) ≈ 73s ｜ 混合 0s（本例未用 C，因关键帧多已满屏）。
**呼吸节奏**：前 1 分钟以人讲为主（0:10–0:57 连续讲核心），中段 1:07–2:00 几乎全动效（公信力/数据/climax），收尾树图纯动效。
