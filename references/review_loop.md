# 验收迭代：从用户截图到下一版

口播包装不是一次做对的活。test-01 从 v4 到 v18 共 14 版，每版都是
「用户甩几张截图 + 一句话」→ 定位 → 改 → 静帧验证 → 重渲 → 交付。
这篇是把这个过程里**真正起作用的方法**固化下来。

## 1. 单轮闭环（约 15–20 分钟）

```
用户截图 + 口语反馈
  ↓
① 先把口语翻译成「可执行的视觉/动效问题」（不要照字面改）
  ↓
② 定位代码：时间点 → TITLES/seq 采样 → stage 应用段
  ↓
③ 改 + node --check
  ↓
④ check-frames.mjs 渲染 3–8 张关键静帧，逐张目检（关键！别跳过）
  ↓
⑤ 只重渲受影响的分段 → verify_segments.py → concat → 混音
  ↓
⑥ 成片抽帧 QC（输出侧 seek）→ 交付 + 说明改了什么
```

**第 ④ 步不能省**。整段渲染 5–10 分钟，而静帧只要几十秒；
静帧没看就交付，等于把用户当 QA。

## 2. 翻译口语反馈（这一步最容易做错）

用户的反馈是观看感受，不是技术方案。常见映射：

| 用户说 | 实际是 |
|---|---|
| 「还是有阴影」 | 某个 mesh 的 `visible` 没关 / 影子位置没跟随终位 |
| 「这个竖线不要」「不明白这装饰什么意思」 | 装饰性线条，直接删（图+文不加装饰线） |
| 「零落的位置太低」 | 强调元素落点要在视觉中心，不在底部 |
| 「图片不要抖」 | 停留期有持续的 sin 抖动/呼吸缩放，删掉 |
| 「间距太大」 | 违反格式塔：列举间距要小于元素高度 |
| 「放大再回去要回到原来状态」 | 缩放回落没回到 1.000（常因另一个状态量叠加了 -4%） |
| 「元素交换时有叠影」 | 出场/入场时间重叠，需要硬间隙 |
| 「82.4 是什么意思」 | 数值语义不自明，换状态词 |
| 「隔板出现太早」 | 附属元素（衬底/隔板）先于宿主出现，要编组同动 |
| 「内容没对上 / 动画滞后」 | 音画错位（多半是 concat 时某段没音轨或多帧） |

## 3. 定位技巧

- **按时间点反查**：字幕里那句话的秒数 → `seq2.js` 的 `TITLES`（有 `i`/`o` 入出点）
  → 对应 `stage2.js` 的应用段（搜时间点常量，如 `seg2(t, 66.60, ...)`）。
- **看不懂画面上是什么东西** → `window.film.debugVis(t)` 列可见 mesh（屏幕坐标+尺寸）。
- **半透明灰团/黑影** → 八成是某个 `makeShadow` 或新 mesh 停在原点，grep 所有 `visible` 赋值点。
- **音画错位** → 不要猜，`ffprobe` 逐段比对 v/a 时长；必要时 30ms 包络互相关确认偏移秒数。

## 4. 交付说明的写法

每版交付要**逐条对应用户提的点**，说清「原来看起来是什么样 → 现在是什么样 → 为什么」，
并把新确立的原则写进 SPEC。用户是靠这个确认你真的理解了，而不是碰巧改对了。

反例：「已优化排版」。
正例：「52s 那组元素重心在 y≈930（画面下部），上方空 400px；整体上移 190px 后重心落在 y≈700」。

## 5. 沉淀节奏

- 每确立一条原则 → 立刻写进项目的 `SPEC.md`（风格真值）。
- 每踩一个工程坑 → 写进技能 `references/native_engine.md` 的坑位清单。
- 通用原则（非本项目专属）→ 捞到 `references/design_principles.md`。
