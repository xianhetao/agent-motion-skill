# 交付后清理：只留定稿物

口播包装工程的中间产物会**指数膨胀**——逐帧 JPEG、各版本成片、历史测试段、QC 抽帧。
test-01 做到 v19 时，`film/` 已经 3.7 GB，其中真值（源码 + 素材）只有 1.1 GB。

定稿后必须清理，否则下一次接手的人（包括你自己）面对 90 个 `sample-*.mp4` 无从下手。

## 1. 先分类，别急着删

按「能不能重建 / 是不是真值」分三类：

| 类别 | 例子 | 处理 |
|---|---|---|
| **真值（保留）** | 源码 `src/`、入口 `index.html`、渲染脚本、素材 `assets/`、规范 `SPEC.md`、拼接方案 `concat-list-*.txt`、源片与字幕、成品段的构件（5 段 sample + 外插段）、最终成片 | 保留 |
| **可重建的中间产物（删）** | 逐帧目录 `frames-sample/`、`frames-check/`、QC 抽帧图、各版本成片 `film-final-v2~v18`、历史测试段 `sample-*`、早期拼接试验 `video-joined*`/`_concat*` | 删 |
| **待定（问用户）** | 早期方案的素材（分镜段、抠像原始序列）、过程性分析文档 | 先列出来问 |

**保留成品段的构件**（而不只是成片）很关键：下次只改一处时，重渲那一段再 concat 即可，
不必全片重渲 15 分钟。

## 2. 执行规则（个人目录，务必守）

1. **先出只读报告**：类别 / 数量 / 体积，让用户选清理档位（保守 / 彻底），不要直接删。
2. **白名单保护**：把成片、构件、真值写进脚本的 KEEP 集合， glob 命中也跳过。
3. **进废纸篓，不用 `rm`**：macOS 自带 `/usr/bin/trash`（无需 brew）。
4. **分批 ≤10、每批验证**：调 trash 后检查文件是否还在，失败立即停。
5. 删完复核：交付区应只剩最终成片；真值目录体积与预期一致。

```python
# 清理脚本骨架（完整版见项目里的 /tmp/cleanup_test01.py 思路）
KEEP = {成片, 五个构件段, 外插段, 规范文档}
```

## 3. 体积参考（test-01，142s 竖屏）

- 逐帧目录 `frames-sample/`：**724 MB**（4275 帧 JPEG q92，720×1280×DPR2）
- 各版成片 `film-final-v*.mp4`：每版 ~40 MB × 30 版 = **1.3 GB**
- 历史测试段 `sample-*.mp4`：90 个 **251 MB**
- 素材 `assets/`（含人物抠像序列 8564 帧）：**1.1 GB**（必须保留，渲染要读）
- 源码 `src/`：**112 KB**

一轮清理回收 **3.6 GB**，工程从 3.7 GB 降到 1.8 GB。
